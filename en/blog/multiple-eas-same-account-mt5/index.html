Several EAs on one MT5 account: magic numbers and total risk

Combining several EAs with different strategies smooths the curve: when one is on a losing streak, another may be winning. But it has to be set up properly so they don't close each other's trades or add up to more risk than you think.

1. A different magic number for each EA

The magic number is a tag the EA puts on every order. A well-built EA only manages positions with its own magic number, so it doesn't touch the others or your manual trades. If you run two copies of the same EA (for example on two symbols or with two settings), change the magic number on one of them.

2. One chart per EA

In MT5 each chart can only hold one EA. Open an XAUUSD chart for each EA, on its correct timeframe, and load its inputs. Save everything as a profile (File → Profiles) so you can restore it if you reinstall MT5.

3. Add up the risk

This is the most common mistake. If you have four EAs risking 0.3% per trade and all four open at once, you have 1.2% at stake. And if they all trade gold, their trades are correlated: a sharp move can stop out several at the same time. Practical rules:

  • Work out the maximum simultaneous risk: risk per trade × number of EAs.
  • If that feels like too much, lower each EA's risk rather than removing EAs.
  • Combine different strategies (trend, momentum, crossover) rather than several similar ones.

4. Check the margin

Several open gold positions use margin. With low leverage or a small account, one EA may be unable to open because the others are already using the margin. Well-built EAs check margin before each order, but leave some headroom.

5. Daily limits per EA and per account

Each EA's daily loss limit is calculated on its own trades. If you need a limit for the whole account (for example on a prop-firm account), set each EA's risk so that the sum of their limits stays below it.

6. A VPS so nothing stops

EAs only trade while MT5 is open and connected. A VPS close to the broker's server keeps everything running 24/5 and reduces latency.
